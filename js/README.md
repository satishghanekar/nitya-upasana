# Scripts

There is no build step: the browser loads these files as they are.

- `parts.js` and `render.js` are plain scripts. `render.js` turns a piece's data into HTML (`renderPiece`, called by `core/page.js` when a piece is first opened, by `print/compose.js` and by `text/search.js`) and holds the Kannada-letters switch (`SCR`).
- The texts are files (`../content/texts/`). `text/load.js` fetches them with `../content/library.json`, `text/content.js` turns them into the pieces' data (`CONTENT`, read with `text/format.js`), and `render.js` puts the pieces into the page. `main.js` waits for this before it starts the parts, so they find the page as if the pieces were written into it. These three are plain functions with no start-up work of their own; `text/format.js` and `text/content.js` touch no page at all, so the unit tests run them in Node.
- `text/load.js` also fetches `../content/routines.json` (the Today card's default routine) and `../content/festivals.json` (the festival rules the Vedic calendar marks), `../content/holidays.json` (its public holidays) at the same time, into `loaded`; without them the texts still load (no routine, no festivals marked).
- `store/` keeps the people on this phone and their settings and routines: `store/db.js` opens IndexedDB (database `nitya`, stores `meta` and `profiles`) with a one-second limit and one retry, falling back to memory; `store/migrate.js` upgrades settings saved by every older version and splits them into a person's part and the device's part; `store/profiles.js` is the profile model and the start-up plan; `store/store.js` holds them while the page is open and writes them back in order (with each person's routine, `routine()` / `setRoutine()`); `store/backup.js` writes and reads the `.nitya` backup file (with its SHA-256). `migrate.js`, `profiles.js` and `backup.js` touch no page; all five are unit-tested in Node (with fake-indexeddb). `main.js` waits for the texts and `openStore()` together before it starts the parts.
- `main.js` is the site script. It is an ES module (`<script type="module">`), and it imports one part per topic from `core/`, `text/`, `store/` and `features/` (`features/overlays.js` and the `print/` files are imported by the parts that use them). `print/` holds the print layout, used by `features/print.js`.

## How the parts fit together

- Loading a part only defines its functions and variables. Each part's `init()` does its start-up work (reads the page, adds listeners), and `main.js` calls the `init()`s in a fixed order. That is the order the code ran in when it was one file (`app.js`), so a part can rely on everything above it in `main.js` being ready.
- A part imports what it uses from other parts by name, for example `import { P, save } from "../core/state.js"`. Functions can be imported in any order. A variable belongs to the part that sets it, and other parts only read it.
- A value several parts read belongs to the one part that sets it, and the others import it (an imported variable can be read, not changed): `FSA` (the fitted text size) in `text/autofit.js`, `rmkPop` (the open dhrupad bubble) in `text/dhrupad-markers.js`, `skCache` (the next Sankashti) in `features/sankashti.js`, and `LEAD` (the leading language, set by `apply()` through `setLead()`) in `core/state.js`.
- The settings are `P` (`core/state.js`): the person reading's settings joined with the device's. `change({ key: value }, then)` is the one way a part changes them: it puts the values into `P`, runs `then` (usually `apply()`), and saves (`save()`). `save()` writes them at once to localStorage (`aarti2-prefs`, with `pid`, the person's id: the boot copy, read first at the next start and by `render.js` before the scripts run) and, a moment later, into that person's profile in IndexedDB (`store/store.js`). Switching person replaces `P` in place (`setAll()`, then `applyPrefs()` in `features/profiles.js`). `apply()` (`features/bars.js`) turns `P` into the `data-*` switches on `<html>` that the styles react to (see `../css/README.md`).
- A new file must also be added to `parts.js`, so it is kept for offline use. `tests/site-files.spec.mjs` checks this.

## Parts, in start-up order

|---|---|
| `core/page.js` | Page basics: the <html> element, the short message (flash), and the pieces on the reading page: `pieceEl(id)` builds a piece the first time it is opened, `onPiece(fn)` is how a part adds its step for each piece built, `secs` the pieces built so far |
| `core/state.js` | Settings (P): the boot copy in localStorage and the person's profile (`store/store.js`, opened by `main.js` before the parts start) |
| `core/words.js` | Helpers for writing words on the page, shared by the parts that build their own HTML: `esc`, Devanagari digits (`dv`, `num`), the menu language (`ui`), the reading languages (`lead`, `second`), Marathi in the chosen script (`scr`, `scrKey`, `mrLang`) and the month and weekday names (`MONTHS`, `DAYS`). Pure, unit-tested in `tests/unit/words.test.mjs`; no `init()`. Use these rather than writing a copy in a part (`text/content.js` keeps its own `esc`, so the text parser does not depend on the settings) |
| `core/features.js` | Switches for features that can be held back (`FEAT_SW`: Landscape printouts, on) |
| `features/day-picture.js` | The app's picture follows the time of day (sunrise, midday, sunset) with today's weekday star ringed; checks again at 12:00, 17:00, midnight and when the page comes back into view |

| `features/library.js` | The Library by category: builds the Library's list (`#jl`) from `content/library.json` and `content/categories.json` with this phone's changes, one `.tocg` per category with texts (empty ones left out), each text with its reading-page number; "Edit categories" / "विभाग बदला" (`#lbb`) opens the categories sheet (`#lbm`, over the Library, with its own Back step, focus trap, Escape, live announcements): add, rename (built-in ones only on this phone; Use the original name), delete a family category, move a text. Words in the menu language, names in the reading languages as in `features/vedic-calendar.js`. Saves with `setLibrary()` (`store/store.js`, `meta.library`, per phone, in backups) and rebuilds the list, titles and search index; `refresh()` after a restore; `textsForSearch()` and `categoryOfSection()` for search |

| `features/astronomy.js` | Astronomy: sun and moon positions, tithi, moonrise and the Sankashti rule (worked out on this device) |
| `features/sankashti.js` | Sankashti: the place (the reader's own from Settings → Place for moonrise, else the time zone's city), the next Sankashti (kept in `shared.skCache` for the Share message), and on a Sankashti day only one line on the home page (`#skt`) with moonrise and the place |
| `features/today-card.js` | Home: the picture beside today's date in Marathi and English, the Morning / Afternoon / Evening switch (tabs, opened at the session for the time now; a session with nothing set today greyed, aria-disabled) with the picked session's texts (from the reading person's routine), Edit beside the session's heading and Add texts in an empty session (they open the routine builder); a title starts the session from there, its texts built and shown in one scroll in session order (`runMark()`, `runBuild()`); on wide screens Home's column stays beside the text being read, with that text marked (`markNow()`, called by `features/bars.js` `mark()`); while a session is being read, ‹ Prev and Next › stay in it (`sessionStep()`, read by `features/bottom-bar.js`; Prev on the first and Next after the last go Home), and the bottom bar's Print prints it (`runIds()`, read by `features/print.js`) |
| `core/panchang.js` | The Vedic calendar (panchang), worked out on this device from `features/astronomy.js`: `dayPanchang(date, place)` (tithi, nakshatra, yoga, karana with their end times, sunrise, sunset, moonrise, amanta month with adhika, Shaka year and samvatsara, ritu, ayana, as at that day's sunrise) and `monthPanchang(year, month, place)` (each day's tithi at sunrise, kshaya and vriddhi, purnima, amavasya, Ekadashi, Sankashti). | `core/holidays.js` | Public holidays from the rules in `content/holidays.json`: `holidaysBetween(from, to, place, list)`, `holidaysInMonth(year, month, place, list)`; a date, the nth weekday, days from Easter (`easter(y)`), or a tithi (through `core/festivals.js`) |
| `core/panchang-names.js` | The panchang's names in Marathi and plain English (IAST comes from the Marathi; tithis, months, nakshatras, yogas, karanas, weekdays, samvatsaras, ritus, ayanas); plain data |
| `features/vedic-calendar.js` | The Vedic calendar: the line on Home (`#pan`: month, paksha, tithi, nakshatra, Shaka year, samvatsara, sunrise, sunset, place; today only, worked out just after the page shows) and the calendar page it opens (`#cal`, like the Library: Back, the phone's Back, Escape): the day card and the month as a table of day buttons (arrow keys, Page Up / Down); a month is worked out only when shown.
